# Internationalization (i18n)

The website and generated category documentation are locale-driven. English (`en`) is the fallback language and Persian (`fa`) is included with RTL support.

## Files

```text
data/locales.json

data/locales/
├── en.json
└── fa.json
```

A locale contains:

- `meta` — language code, display/native name, and `ltr` / `rtl` direction;
- `ui` — interface labels and generated Markdown labels;
- `categories` — category titles;
- `platforms` — platform labels;
- `limitations` — short limitation / “things to know” labels;
- `notes` — translated notes keyed by mapping ID.

## Add another language

For example, to add Spanish:

1. Copy `data/locales/en.json` to `data/locales/es.json`.
2. Set `meta.code` to `es`, `meta.native_name` to `Español`, and translate the values.
3. Add `"es"` to `data/locales.json`.
4. Run `python scripts/validate.py`.
5. Run `python scripts/generate.py` and `python scripts/build_site.py`.

No changes to `website/index.html` or `website/assets/app.js` are needed. The language selector is generated from locale metadata.

## Fallback behavior

The frontend falls back to English when a runtime lookup is missing. CI is stricter: for committed locales, `scripts/validate.py` requires complete UI/category/platform/limitation/note coverage so missing translations are caught before deployment.

## RTL

The locale's `meta.direction` controls the document `dir` attribute. CSS uses logical properties such as `margin-inline` and `inset-inline-start`, so RTL languages do not need a separate stylesheet.
